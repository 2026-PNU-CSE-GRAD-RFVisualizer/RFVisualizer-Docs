- 기준일: **2026-08-12**
- 목적: 모든 팀원이 현재 상황과 앞으로 할 일을 5분 안에 파악한다.
- 전제: Network Backend의 최종 실험 Run·TestSegment·Export 구현이 완료되었다고 본다.
- 기술 세부사항: [AI_HANDOFF_REFERENCE.md](AI_HANDOFF_REFERENCE.md)

> **결론:** 이제 최우선은 3층 ㅁ자 복도의 장면과 좌표를 확정하고, `고정 센서 4대 연속 기록 + 이동 센서 1대·위치당 2분` 방식으로 최종 데이터를 다시 측정하는 것이다. 측정과 논문 결과를 먼저 확정한 뒤 SIBR Viewer와 휴대 장치 통합으로 넘어간다.

### 4층 결과의 위치

- 4층 결과는 전체 파이프라인의 가능성을 확인한 **Pilot Evaluation**으로만 남긴다.
- 최종 정확도나 일반적인 우수성을 주장하는 근거로 사용하지 않는다.
- 최종 논문 수치는 3층 재측정과 QC를 통과한 뒤 확정한다.

## 3. 1단계: 네트워크 인수 확인

새 기능을 더 만드는 단계가 아니라, 최종 측정에 사용해도 되는지 확인하는 단계다.

### 확인할 것

- [ ] 센서 5대 사전·사후 Offset이 서로 다른 ID로 저장됨
- [ ] C1~C4가 Test 이동·안정화 중에도 계속 저장됨
- [ ] T 데이터는 Test의 실제 2분 기록 구간에만 포함됨
- [ ] Test와 같은 시간의 C1~C4 데이터가 `segment_id`로 연결됨
- [ ] 정방향·역방향과 재측정 데이터가 서로 덮어쓰이지 않음
- [ ] 브라우저 새로고침 후 Run과 타이머가 복원됨
- [ ] MQTT 끊김·재연결과 최대 데이터 공백이 QC에 기록됨
- [ ] SQLite, JSONL, CSV/JSON Export가 모두 생성됨

하나라도 실패하면 최종 측정을 시작하지 않고 리허설에서 먼저 해결한다.

## 4. 2단계: 3층 장면과 좌표 준비

### 현장 측량

- [ ] 복도 폭·높이·둘레와 네 코너 측정
- [ ] 공유기 위치·높이·방향 기록
- [ ] C1~C4와 T1~T10 후보 위치 표시
- [ ] 모든 센서 높이를 1.2m로 통일
- [ ] 문·유리·엘리베이터 상태 사진 기록
- [ ] 길이 검증용 기준점 3개 이상 표시

### 촬영

- 카메라 초점과 밝기를 고정한다.
- 약 1.4m 높이에서 천천히 걷는다.
- 시계 방향 전체 → 반시계 방향 전체 → 네 코너 상세 순서로 촬영한다.
- 출발점과 도착점은 같은 장면이 충분히 겹치게 촬영한다.
- 원본과 백업 영상을 모두 보관한다.

### 장면 합격 기준

- 사진의 95% 이상이 하나의 3D 복도로 연결됨
- 카메라 경로가 끊기거나 벽을 통과하지 않음
- 출발점과 도착점 차이가 0.3m 이하
- 실제 길이와 3D 모델 길이 차이가 2% 이하
- TX, C1~C4, T1~T10이 같은 좌표계를 사용함

크게 실패하면 센서 측정 전에 다시 촬영하거나 미터 보정을 수정한다.

## 5. 3단계: 3층 최종 측정

### 고정 조건

- **Calibration 센서 4대:** C1~C4에 고정하고 Run 전체 동안 연속 기록
- **Test 센서 1대:** T1~T10을 이동하며 위치당 2분 기록
- **공유기:** 위치·높이·BSSID·채널·출력 고정
- **센서:** 높이 1.2m, 방향과 거치 방식 고정
- 문·엘리베이터·보행자 등 환경 변화는 기록

### 한 회차 순서

| 순서 | 시간 | 작업 |
|---:|---:|---|
| 1 | 5분 | 센서 5대를 한곳에 모아 사전 Offset 측정 |
| 2 | 약 30~45분 | C1~C4 연속 기록과 T1~T10 이동 측정 |
| 3 | 위치당 20초 | T 도착 후 안정화 |
| 4 | 위치당 2분 | TestSegment 기록 |
| 5 | 5분 | 센서 5대를 다시 모아 사후 Offset 측정 |

- 정방향: `T1 → T10`
- 역방향: `T10 → T1`
- 가능하면 정·역방향을 별도 Run으로 수행한다.
- 다음 Test는 사람이 센서를 옮긴 뒤 직접 시작한다.

### 가장 중요한 비교 원칙

예를 들어 T4를 `14:08~14:10`에 측정했다면, C1~C4도 **같은 14:08~14:10 기록만** 사용한다.

- C1~C4의 전체 Run 평균을 모든 Test에 공통 적용하지 않는다.
- 시간 매칭은 Backend의 `server_ts_ms`를 기준으로 한다.
- 평가 단위는 Raw Sample 개수가 아니라 위치별 대표 RSSI 중앙값이다.
- 위치당 정상 기록이 100개보다 적으면 현장에서 재측정한다.

## 6. 4단계: 현장을 떠나기 전 데이터 확정

### 필수 확인

- [ ] 정방향 T1~T10이 모두 완료됨
- [ ] 역방향을 수행했다면 T10~T1이 별도 Run으로 남음
- [ ] 각 TestSegment에 T와 C1~C4 데이터가 모두 존재함
- [ ] Test와 Calibration의 시간 범위가 정확히 일치함
- [ ] 좌표·높이·역할·BSSID·채널이 빠지지 않음
- [ ] Sample 부족, 긴 공백, 연결 끊김이 QC에 표시됨
- [ ] 사전·사후 Offset과 장비 변화량이 저장됨
- [ ] 폐기·중단된 Segment가 최종 결과에서 제외됨

### 현장 백업 묶음

```text
SQLite DB
JSONL 원본
전체 Export 디렉터리
qc_report.json
측량·좌표표
문·유리·엘리베이터 상태 사진
Run 진행 화면 캡처
원본 촬영 영상
```

노트북과 별도 저장장치에 각각 한 벌씩 복사한 뒤 현장을 떠난다.

## 7. 5단계: RF 분석과 논문 결과 확정

### RF 분석 순서

1. 3층 Proxy와 실제 좌표로 Raw Sionna RT 결과 생성
2. Test와 동시간 C1~C4 데이터 연결 확인
3. Plain IDW 계산
4. Global Bias 계산
5. Residual IDW 계산
6. 정·역방향 반복 차이와 위치별 오차 확인
7. MAE, RMSE와 공간적 경향 비교

비교 방법은 다음 네 가지를 모두 표와 그림에 포함한다.

| 방법 | 목적 |
|---|---|
| Raw Sionna RT | 보정 없는 물리 시뮬레이션 기준 |
| Plain IDW | 실측 Calibration만 사용한 공간 보간 |
| Global Bias | 전체적인 RSSI 차이 보정 |
| Residual IDW | 시뮬레이션의 위치별 잔차 보정 |

### 논문 반영

- 4층 결과는 Pilot Evaluation 절에만 사용한다.
- 3층 결과를 최종 정량 표와 Figure에 사용한다.
- 구현됨·실물 검증됨·논문 근거로 확정됨을 구분한다.
- 반복 차이가 크면 숨기지 않고 한계점과 재현성 결과로 기록한다.
- 최종 수치는 Export와 분석 스크립트로 다시 생성 가능한 값만 사용한다.

### 네트워크·임베디드

자동 위치 추정은 기본 범위에서 제외한다. 먼저 버튼으로 T1~T10 같은 미리 정한 위치를 선택하는 시연을 완성한다.

## 11. 시작·종료 판단 기준

### 최종 측정을 시작하지 않는 조건

- 3층 3D 모델이 끊기거나 실제 크기와 맞지 않음
- TX, C1~C4, T1~T10 좌표가 같은 좌표계로 준비되지 않음
- 센서 5대가 안정적으로 수신되지 않음
- Test와 동시간 Calibration Export가 리허설에서 확인되지 않음
- Offset·BSSID·채널·역할·시간 정보가 결과에 남지 않음

### 최종 측정을 완료로 보지 않는 조건

- T1~T10 중 하나라도 정상 데이터가 부족함
- 어떤 TestSegment라도 C1~C4 중 한 센서의 동시간 데이터가 없음
- 좌표나 환경 기록이 빠짐
- QC 결과와 원본 백업을 확인하지 않음

### 논문 결과를 확정하지 않는 조건

- 분석 수치가 원본 Export에서 재현되지 않음
- 정·역방향 또는 반복 안정성을 확인하지 않음
- 4층 Pilot과 3층 최종 결과가 같은 표에서 혼동됨
